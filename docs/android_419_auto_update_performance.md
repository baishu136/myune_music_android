# Android 419：自动更新下载与播放控件开销

本轮基于已同步的418，版本1.0.0+419，正式ARM64 versionCode2419。新增设置→常规→「自动检测更新并下载」，默认开启，持久保存。软件内更新日志继续只记录实际GitHub Release，413～419待下一次获授权发布归并；本轮不提交、推送或发布Release。

## 更新与下载

- 启动/回前台后延迟4秒，避让当前手势或切页。成功检查后6小时内不重复自动检查，网络/API失败后至少1小时再试，无常驻轮询。手动检查不受间隔或自动开关限制。异常类型、负数或明显超出间隔的保存时间安全回退，不让坏记录阻断更新。
- 读取项目真实GitHub Release，跳过草稿和预发布，比较有效Android版本号；只接受项目正式附件路径中的ARM64 APK，不下载源码ZIP或旧于当前版本的包。没有兼容APK时手动入口仍可打开对应发布页。
- 传输、断网重试和通知由Android系统DownloadManager负责；应用只在完成事件、前台恢复和用户刷新时查状态。下载不经过歌词/音频线程；文件大小、SHA256（发布方提供时）、包名、版本和当前签名由独立原生工作线程验证。
- 自动下载使用非计费网络，不漫游；用户手动检查下载可使用计费网络。关闭开关会废弃迟到的自动检查结果，并取消应用自己尚未完成的自动下载，已完成包保留。相同有效附件不会反复下载。
- 完成后可手动打开系统安装流程；系统尚未允许该应用安装来源时只打开系统授权页，不自动授权或安装。REQUEST_INSTALL_PACKAGES仅用于用户点击后的系统流程。已安装版本的旧下载不再显示为可用更新。
- 下载保存在应用自己的外部文件目录，不改歌曲、歌词或用户下载目录中的其他文件。普通播放和输出管理器保持原结构，无额外播放器、音频回调或后台唤醒锁。

## 已实施的性能修改

1. 播放进度条保留Material样式、拖动和可访问性，只有位置变化达到约四分之一物理像素才重建；预览和大幅跳转立即响应。歌词和原始播放时间不降频、不量化。隐藏页/后台停止监听，恢复时重新取实际位置。测试中100次10ms推进只允许少于22次Slider重建，误差限制在65ms以内；这是给定尺寸/歌曲时长下的视觉阈值，非所有设备固定刷新间隔。
2. 歌词正播行定位复用同一进度事件已计算的视觉时间，省去重复投影。相同歌曲路径在同步配置中直接命中，不在每次进度通知时反复替换路径分隔符和转换大小写。保留设备/歌曲偏移独立、倍速、seek和原逐字时间边界。
3. 更新状态使用独立、低频通知，不把下载进度接到播放或歌词Provider。校验和文件读取不进入UI线程。

歌词曲线、上浮、共享帧时钟、普通/逐字缓存、弹性运动、背景、模糊和音效均保留，不以关闭特效取得测试结果。

## 其他区域的开销审查

- 主页保活和首屏封面缓存用于避免切页冷初始化，当前不缩小缓存或强制卸载页面，以免重新引入手势帧的解码/分组工作。
- 封面、普通行和逐字行已有有界缓存、下一行准备及隐藏暂停；本轮减少其上游重复进度处理，不再添加第二个动画时钟或逐帧计时器。
- 动态背景仍是原单次统一参数计算和质量/生命周期调度。本轮没有重测全屏动态背景GPU，不能依据静态底色歌词样本声称背景耗电降低；进一步修改需单独做同封面、同质量的GPU对照。
- 弹性复杂混排仍是后续重点：需要更长样本定位行边界的缓存准备与绘制尖峰，不能凭平均帧耗时改掉原逐字/回弹语义。
- 音频DSP、AAudio缓冲和设备恢复不改，不削减音频安全余量来换CPU数字。本轮没有新的USB、端到端声学、RF或长时后台音频验收。
