# 417 后台播放稳定性（2026-10-22）

用户反馈正式包和独立包均出现后台声音断续。手机两包当时实际均为416，不是415/416版本对照。保持现有播放器、解码、队列、音效、歌词与同步配置，修复可确定的输出恢复和后台服务缺口；不通过通信模式切路由，不改系统安全或电池设置。

## 修改

- 正常AAudio断连由mpv先自行重建；900ms后统一核对真实输出，已恢复的流保持不动。密集相同通知合并，媒体解码错误不触发设备重载；真正失效才恢复兼容输出，记录不能确认实际设备的状态。
- 用户选择设备取消旧恢复，准备设置阶段不先重载旧设备，最终只重载一次；重复选择同一已确认设备不重载。短暂设备列表缺口和USB回执过渡先等待稳定再判断，不新增持续轮询。
- 对普通共享、非低延迟、系统自动容量流请求200ms设备缓冲余量；读取实际容量后不超过容量、不缩小现有缓冲。独占、低延迟和用户指定容量保持，不修改PCM/音量/均衡器，不增加音频数据回调的锁、日志或分配。原500ms播放器缓冲保留；两种缓冲不混淆，也不重复扣除歌词时间。
- 媒体后台服务验证异步连接，5秒超时，失败最多三次退避重试；控制器断开和服务意外销毁可恢复。正常稳定10秒后允许下一次独立故障重新取得重试预算；关闭时撤销回调，旧回执不复活服务。原播放意图控制唤醒锁，缓冲/seek不把它误当用户暂停。
- 已持有音频占用时，重复媒体状态推送不再清除等待自动恢复的标记；实际重新获准时更新状态。保留系统对通话/设备拔出的暂停规则。

## 真机方法和边界

vivo V2352A / Android15，独立com.myune.music.benchmark 2417/ARM64，升级前验证包名、ABI与版本，数据不清。测试使用自己的低音量FLAC。测试期间暂停正式包，避免两路同时播放干扰；不将整个混音器其他应用的计数归因于Myune，按测试进程和轨道身份读取。

此手机persist.sys.log.ctrl=no，进程logcat为空，未更改全局日志设置。空日志不能证明无错误；以AudioFlinger实际轨道帧计数/Underruns、媒体状态、前台媒体服务和播放唤醒锁为主要证据。系统轨道缓冲与请求值分开说明，不能当作无线声学测量。

旧416短时蓝牙基线未复现持续断流，不能凭此声称找到每次断续的唯一原因。未连接USB DAC，不宣称USB独占或Bit-Perfect硬件通过。强制停止整个进程后持续播放不属于本轮能力。
