# Android 369：主页空闲预热与播放页入场分阶段准备

日期：2026-10-06。版本 `1.0.0+369` / `1.0.0-android.369`，正式 ARM64 versionCode 2369。用户明确授权实施推荐方案并在真机验证。以工作区 368 的完整快照为基线，保留 361–368 的全部已有修改和留档，未提交、推送、发布 Git，也未卸载或清空正式数据。

## 实现边界

- 五个主页共享原 300ms 两端点切页场景。生产入口开启渐进预热，首个页面正常启动，其余页面逐个领取 maintenance 空闲工作许可；完成数据准备后，再领取许可挂载、布局和屏外绘制一帧。拖动、切页、后台或其他路由覆盖期间不挂载新的主页。隐藏页面关闭 Ticker 和焦点，不启动多屏的远距离封面预取。
- 用户在预热完成前立刻访问冷页时，保留页面位置和容器，内容在手势/过渡结束后准备，不把首次挂载重新塞回滑动帧。这个取舍可能短暂显示空白内容；没有强行等待预热才响应导航。预热后的主页切页主要改变已有场景的绘制位移，仍有顶部标题、导航选中状态等必要状态更新，不承诺应用整帧完全不 build/layout。
- 曲库标题、歌手、专辑与歌单标签的拼音、混合字符排序键、搜索索引和歌手/专辑分组由常驻 isolate 准备。只发送字符串与分组索引，不复制封面或播放器对象。主 isolate 每 128 首组装一批输入，批次间若发生手势则释放许可并重新等待空闲，随后在空闲许可下发布；曲库修订、分隔规则及请求代际不一致时丢弃旧结果。worker 在启动中销毁也会结束待处理请求。字典初始化不再由主页首次分组/搜索触发。准备前普通文本搜索仍可用，拼音搜索在索引就绪后重新计算。
- 歌手/专辑页按曲库修订和准备状态刷新；手势期间复用上次准备好的页面，结束后才重新排序、建索引和选择代表封面。歌曲标题/歌手排序保留原字符级拼音比较规则。
- 页面挂载时按实际首屏尺寸解码封面；Mini Player 对当前曲目按播放页目标像素尺寸在空闲 userVisible 优先级预解码。其优先级高于隐藏主页及相邻曲目维护工作，低于已可见图像。最多保留一张当前歌曲的图像流监听，换曲、缓存代际变化及销毁时释放，单图超过 8MiB 不长期钉住。监听收到的 ImageInfo 克隆即时 dispose。没有扩大全局图片缓存。
- 播放页入场保留路由、Hero、封面及维持原封面几何位置所需的轻量布局。控件、进度监听和背景在 route 完成后分别领取空闲许可，隔帧挂载；后台暂停，恢复后继续。原背景效果和歌词绘制方案保留，歌词继续按原入口延后准备。必要路由/Hero/首帧布局仍有开销，这次没有预先挂载整个播放 route。
- 屏外绘制只证明布局/绘制数据准备，不能保证 GPU 上传、shader 编译或系统回收后仍常驻。字体/语言/窗口尺寸/排序规则变化、曲库更新、图片缓存淘汰仍需重新准备；没有把所有运行期变更视为永远热缓存。

## 验证方法

设备为 vivo V2352A、Android 15，序列号 `10CEB70TQE001E2`。使用独立包 `com.myune.music.benchmark` 的 ARM64 Profile，安装前逐次 aapt 校验独立包名、2368/2369 版本及单 ARM64 ABI；入口在写数据前核对实验专属目录，正式应用未被诊断入口写入。

368 与 369 都通过真正的应用入口、播放器、五个主页及完整播放 route。固定 95 首真实本地歌曲、9 个诊断歌单，同一深色主题及歌单卡片设置；实验静音后暂停，不复制音频进生产资源。每轮包含启动后立即真实指针滑动、空闲预热后 18 次主页导航、3 次播放页进出、一次清图片缓存后的主页切换，总计 26 个测量阶段。使用 Flutter FrameTiming 原始微秒数组，分别统计动画窗口及包含后续准备的完整采样窗口，采样期间不录屏。

屏幕 API 报告约 120Hz，但实际 vsync 中位数约 16.57ms，即约 60Hz。一次前后顺序对照及最终复测用于发现尖峰，不构成长期、跨机型或随机化统计结论。正式 Release 的截图/录屏用于功能与外观验证，不能当作 Profile 帧时序。
