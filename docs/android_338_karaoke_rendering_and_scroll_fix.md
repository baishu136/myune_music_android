# 338：逐字歌词蒙版、绘制开销与行滚动兼容修复

2026-10-02。实际工作区基线为 0.9.9+337；手机正式应用为 336。本轮递增为 0.9.9+338 / 0.9.9-android.338。已阅读 README、适用目录（未发现 AGENTS.md）、336/337 记录、337 诊断、当前实现及测试。保留现有未提交和未跟踪成果；未更改播放器、主题、歌曲导入或默认配置，pubspec.lock 与修复前一致。

## 查明的问题

1. 336 将合成英文词拆为独立字母后，中途上浮的纯色字母各自使用 saveLayer。诊断长词有 34 个单元，900ms 时有 32 个纯色离屏层。旧后缀蒙版还重复记录多组剩余词元，增加排版缓存构造与原生 Picture 开销。
2. 同一物理行的不同字体 TextBox.top 不相等。旧分组把 A/emoji/B 拆为重叠矩形，再依据总宽估计时序，出现次序反转。复杂字符的横向全宽裁剪会把邻字复制到本单元；多个抗锯齿覆盖叠加造成 .36 透明度文字异常变亮。337 诊断混合字体的灰色覆盖峰值误差为 59（92→151）。仅扩展外层绘制边界不能修复已经裁掉的蒙版。
3. 开启逐字歌词会强制关闭既有弹性行滚动。恢复兼容时不能同时开启整列表归一化位移、行弹性位移和局部 AnimatedSlide。
4. 新的真实帧率回归还暴露出：相邻双语/折行歌词被“大跳转限幅”截短，首帧提前跳过 55.6/65.5dp；连续弹性重定向覆盖残余位移，而不是继承姿态。

## 实际修改

- 以真实 LineMetrics/基线建立物理行分区，只合并相邻的同方向片段；复杂字符保留完整 shaped run。字形查询、选择框和分区均在布局缓存阶段完成。单元覆盖按像素网格分区，垂直覆盖包括行内字形空间；横向不再为一个字体片段占用整行。保留组合字素、连字检测和复杂文字回退。
- 为活动行及临近下一行异步预热一张白色字形图像；纯色字母直接绘制子区域，静止/完成字母合批，只有渐变前沿保留必要的蒙版离屏层。去掉平方级后缀 Picture。异步结果通知 painter 局部重绘，不引起列表 setState。图像最多 1,048,576 像素（4MiB RGBA），最长边至多 4096；不建立每字符纹理或全曲全局缓存。尺寸/字体/字重/语言/文字缩放/DPR 变化失效，纯颜色变化不重新布局；失效、移出缓存区和迟到结果均释放图像/Picture。图像不可用时仍可使用 Picture 回退。
- 80%/下一行前 400ms 的预热现在也能触达已经挂载的下一行，仍只保留一个未挂载备用缓存。释放列表测量用 TextPainter。
- 刚性滚动保留归一化整列表运动；现有弹性选项开启时由行弹簧负责正常换行，整列表不再同时动画。逐字模式始终没有内部 AnimatedSlide。弹性行与逐字时钟共享 LyricFrameClock，去掉每行 Ticker 和延迟 Timer；运动标记也覆盖弹性波，使远处模糊保持离散阶梯。
- 相邻普通双语/折行不再截短行程；仅跳过多行或单条超过两倍视口的异常长段继续限制不可见行程。弹性重定向叠加残余偏移并继承速度。显式 seek、浏览及模式切换清除旧位移。修复最后一个弹性消费者在通知中退出后帧时钟不休眠的问题。
- 高亮与上浮配置、真实词元时间戳、原有视觉补偿和合成配速不变。物理行几何更正影响的是缺少逐字时间时的估算分配，不声称取得了真实咬字时间。上浮仍独立于列表滚动；不叠加缩放/发光新效果或新设置。
