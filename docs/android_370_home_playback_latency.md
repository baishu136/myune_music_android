# Android 370：首页与播放页显示延迟修复

日期：2026-10-08。版本 `1.0.0+370`，显示 `1.0.0-android.370`，正式 ARM64 versionCode 2370。本轮按用户授权实施显示门槛解除、调度预热与播放组件更新范围优化。保留已有 361–369 脏工作区及全部产物；没有提交、推送、发布 Git，也没有卸载或清空正式数据。

## 原因与实际修改

### 首页

369 的五页都调用完整 `prepareLibraryPresentation()`，单个慢任务阻塞后续页。现在歌单和设置页的准备不依赖曲库分组；歌手、专辑只等待分组与分组名称排序键。`HomeTabViewport` 独立启动准备请求，先挂载已就绪页面，当前目标在等待许可期间也可以提升优先级。未就绪页显示轻量进度反馈，失败有界并可点击重试；手势期间仍不挂载冷目标内容，已访问页面和滚动状态保留。

常驻 worker 分两次产出：先分组/名称排序键，再完整歌曲拼音、首字母、混合键和搜索索引。`libraryGroupsReady` 与完整索引就绪分开，搜索补齐不再阻塞分组展示。输入每批最多 128 首且以约 2ms 为目标，批次之间释放许可；请求代际、曲库修订和分隔规则继续校验。分组失败不会被当成永久完成，旧结果不能覆盖新修订。

原首页 controller 在切页开始和结束都重新 pulse 380ms，结束后再次等待；启动乐库入场另有固定 720ms 保护。现在切页与乐库入场使用分别拥有的保护票据，跟随实际完成释放；切往其他页、路由覆盖和销毁会释放对应票据，避免隐藏且被 TickerMode 静音的动画持续占用保护。保留 300ms 首页切页和原乐库入场效果。点击/指针的既有短保护仍存在。

### 播放页

删除 `_controlsReady`、`_backgroundReady` 及入场结束后两阶段挂载链。基础控件、标题、进度与背景从首次构建就存在，随原 620ms route 动画入场；退出仍为 460ms。永久保持 `PlaybackBackground → 内部背景槽 + 前景 Scaffold`，背景资源到位或样式变化只更新背景，不再从 `ColoredBox` 改父节点而重建整片前景。封面和控制区从第一帧使用实际最终布局，不再先保留一个透明控制区占位。

Mini 的当前大封面在后台优先级空闲时启动解码；沿用有界单张图像流保留与缓存代际校验。当前歌曲的缩略图/封面可提前准备流体调色板和 shader program，不创建隐藏播放 route、重复 Hero、shader 实例或动画 Ticker。已缓存背景从入场开始可呈现；缓存缺失时保留现有静态/实时模糊回退，实际效果资源异步接替。没有关闭流体、模糊或歌词效果。

播放 route 使用拥有者独立的开始/完成/销毁保护，避免取消整个全局手势状态。既有后台恢复时流体与玻璃的延迟保护保持不变。

### 调度与组件更新范围

- 主线程空闲许可只覆盖资源启动或短提交，不跨越封面解码、shader asset、背景预模糊、元数据读取、动态颜色提取和播放状态持久化等待；已有资源 worker 并发限制仍保留。元数据批量发布、动态颜色应用继续取得短提交许可，防止等待解除后把重更新塞入手势。
- 队列支持执行时重新读取优先级，最新首页目标可超过已排队的维护任务。不同过渡/乐库入场票据只释放自身；视觉入场仍允许流体运动，纯预热继续等待。
- 播放顶层不再选择播放状态、收藏、播放模式、预设和倍率。收藏、播放/暂停、模式、均衡器标签各自选择所需状态；歌词子树和边缘倍速提示保留独立播放/倍率更新。
- Settings 选择当前播放页使用的配置签名，Theme 选择字体/实际主题和歌词颜色，减少无关 provider 变更引发的页面重建。
- Slider 与原媒体/歌词时钟保持原更新频率；`PlaybackClockBuilder` 仅在经过时间、剩余秒数或总时长文字改变时重建，拖动预览仍及时更新。
- 同一歌曲/notifier 的封面合并 Listenable 保持稳定；播放玻璃复用原 5/7 sigma 固定滤镜。收藏按钮只查询一次对应 bool，没有重写收藏数据结构或播放存储。
- 添加 `NowPlaying.compose` Timeline 范围供后续 Profile/CPU 归因；它记录界面组装，不能单独代替布局、Raster 或实际屏幕可见时间。
