# Android 358：Power-Softmax 抗泛白混色

日期：2026-10-04。基线为实际脏工作区357；保留357歌词跟随、桌面歌词及其他未提交成果。本轮只调整流体背景与必要的色槽元数据、回归测试、版本记录。

## 实际问题与修改

- 原Shader并非字面上的线性Additive，而是四色Screen透射叠加。宽光场覆盖范围扩大后，互补色的通道共同变亮，仍会趋白。改为用户指定的 `exp(-d²*2.2)` 光场、幂次3.2、c1/c3增益1.25/1.15和权重总和归一化（分母加.0001）。不再逐场累积光能。
- 深度采用指定公式 `mix(c0*.40, blendColor, .88)`，即12%的暗色底座，不将文字描述的15–20%与公式混为同一数值。保留宽半径、双层空间域扭曲、一次`.28`演化时钟、弱暗角、dim限幅、静态亚色阶抖动、不透明单次drawRect。
- 旧base/glow字段和Uniform布局暂保留用于兼容Painter/调色板快照，但不再参与Screen混色；未增加纹理、滤镜、saveLayer、每帧取色或新设置。
- 在64×64 worker的直方图入桶前过滤HSL明度>.88且饱和度<.20的高光；直接调色板入口同样过滤，分类仅使用剩余颜料。占比仍以原始可见像素为分母，暖色噪点不会因滤除白底变成重要暖色。全白图明确回退到中性灰，不借用主题伪彩；纯黑保持纯黑。
- 鲜艳封面从现存真实颜料中选择有面积及彩度的c1，饱和度限定.70–.95、明度.35–.55；辅助色与实际暖色c2维持已有保护。增加`vividAccentLocked`，避免控制器最近色槽匹配将高彩c1移走；随插值、快照、相等性与哈希一起传播，不增加逐帧分析。
- 不承诺交界处不会降彩：归一化混色仍会在色域边界过渡；85–95%领地占比和全屏75%饱和度并非这套公式在所有相位/封面下的数学保证。用户提供的78%→14%是问题报告，本轮不将它写成自行实测。

新增5项测试，先在旧实现实际复现高光污染、worker白底入选与Shader公式偏差（3项失败）。最终全量Flutter测试456通过、1项既有截图导出跳过；静态分析无问题；APK审计脚本6项测试通过；`git diff --check`通过。新增实际FragmentProgram渲染与独立标量公式逐像素对照，不只匹配Shader源码；覆盖高光双阈值、白底PNG真实解码、黑白保护、c1/c2槽匹配、单色保持。既有回归继续覆盖650ms连切连续性、全RGB相位回绕、dim、60/90/120Hz调度、有界缓存及路由暂停。

固定合成色样、96×160网格、motion=0、dim=.3：新Shader平均HSL饱和度约.5081，旧Screen数学模型同输入约.4292；新Shader每12×20像素抽样与标量公式误差不超过2个8-bit色阶。不是《Cupid》原封面、全屏所有像素75%保证或真机取色百分比。旧单色光场跨整屏扩散断言已改为领地收敛断言，符合本轮要求；保留中央亮度与相邻帧连续检查。不宣称Salt内部算法已核实或外观1:1还原。
