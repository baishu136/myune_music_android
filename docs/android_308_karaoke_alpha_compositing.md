# 308：逐字高亮透明度修复

## 依据

对比用户提供的 `1 (5).mp4` 和 `2 (5).mp4`：参考视频中单词进行到中段时，前面的字母已经明亮；307 的字母仍接近灰色，词尾一起变白。

使用项目内 MiSans 字体进行实际像素回归：307 中未播放和词内已播放字母的峰值均为 92/255，说明此前参数调整没有解决透明度锁定。

## 修复

- 原来的 srcATop 混色保留灰字透明度，无法将 36% 不透明的字变为完全不透明。
- 改为先绘制不透明字形遮罩，再以 srcIn 同时写入插值后的颜色和透明度。
- 只为处于变化中的字符使用局部离屏图层；已完成和未开始字符直接绘制缓存字形。
- 调整字符重叠窗口，使长词的过渡字符数量受控，避免每个字都创建合成图层。
- 保留字符上浮终点与整词完成后的位移一致，防止阶段切换跳变。

## 验证

新增真实字体像素测试，要求词内已完成字母的亮度接近词尾最终亮度；该测试在 307 失败，在修复后通过。真机结果另见本次留档。

- 静态分析通过；67 项歌词与更新记录专项测试通过。
- 已在 V2352A 上覆盖安装 versionCode 2308，实际录制约 32 秒同曲歌词播放。
- 手机原本关闭逐字歌词，测试时已开启并设为“全部”；原来的高亮歌词设置保持开启。
- 实测帧可见 `couldn't` 由前至后逐字变亮，`cupboards`、`Another evening` 和后续换行显示正常；所查运行日志未发现相关异常。
- 录屏约 60 帧/秒，这不是应用帧耗时统计。系统 gfxinfo 未统计到 Flutter 帧，因此不据此声称零掉帧。
- 留档包含 `device_308.mp4`、局部帧图和本说明；测试完成后暂停播放。
