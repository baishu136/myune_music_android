# Android 400：复制反馈与斜杠合唱歌曲分组

日期：2026-10-16。版本 `1.0.0+400`，正式ARM64 versionCode `2400`。保留398/399未提交成果与历史留档，本轮未提交、推送或创建tag/Release。

## 问题与修改

399只修正了播放页歌曲选择列表匹配第一位歌手的问题，尚未修正主页的歌手分组。默认分隔符仅含中英文逗号/分号及顿号，没有斜杠，因此 `Future/The Weeknd` 被当成一位完整歌手。前台分组与后台预热各自维护拆分实现，且旧正则把多字符自定义分隔符写进字符集合；例如 ` feat. ` 会错误拆开歌手名中的单个字母。

新增共享 `artist_names.dart`：

- 默认分隔符增加 `/` 和 `／`，设置页重置默认使用同一常量。已有完整旧默认集合进行一次性升级，不覆盖真正自定义或空列表。升级标记保证用户随后移除斜杠时不会在重启后再次添加。
- 自定义分隔符按完整字面值识别，较长分隔符优先。去除歌手首尾空白、合并重复空白，按不区分大小写的完整姓名匹配；不使用子串或自动拼写纠错，不把不同姓名合并。
- 同一曲目的重复歌手只记一次，跨曲目大小写差异归入同一组，显示名使用首次出现的清理后名称。歌手每组保留原曲库顺序和不同文件，不按歌名去重。
- `PlaylistContentNotifier`同步分组和 `LibraryPreparationWorker`两阶段预热共用上述解析/分组函数；解析器在分隔符变化时才重建。旧分组不持久化，升级后利用已有歌曲元数据重新生成，不需要重导音频。
- 播放页歌手范围继续匹配当前歌曲全部参与歌手，并使用同一姓名匹配键，修正大小写或多余空白导致的遗漏。保持库版本/分隔符签名、过期后台结果丢弃及原通知刷新机制。

测试示例：`The Weeknd`独唱组包含 `Future/the WEEKND`、`Future／THE   WEEKND` 合唱，但不包含拼写不同的 `The Weekend`。当前播放合唱时，歌曲选择列表仍同时包含各参与歌手的相关作品，任意命中只加入一次。

## 复制成功反馈

剪贴板写入成功且详情行仍挂载后，调用一次 `HapticFeedback.lightImpact`，底部浮动提示框显示固定文案“已复制歌曲信息”，约1.2秒后退出。震动遵循系统触感支持及设置，可选触感失败不影响复制成功反馈。复制失败不震动、不显示成功框，原失败提示仍保留。

歌曲详情使用局部、透明的 `ScaffoldMessenger/Scaffold` 容器，使成功框显示在底部详情弹层之上，避免外层Scaffold提示被弹层遮住。连续复制替换当前成功框，不排队堆积；详情关闭后不留迟到反馈。原主题表面、拖拽高度、信息下划线及完整值复制保持，不增加设置或说明文字；其他全局通知的位置未改。
