# 405 歌词正文缓存与共享滚动进度

2026-10-17，落实404真机诊断的推荐方案。当前 `1.0.0+405`，ARM64正式versionCode2405；基于404全部未提交成果，不提交/推送/tag/Release，不清旧档或应用数据。404诊断记录与历史源码ZIP保持不可变。

## 实现

### 普通歌词正文

- `LyricPlainForeground`继续沿用原生不透明RGB文字与独立alpha。新 `LyricPlainRaster` 保留真正的RenderParagraph作为布局、命中测试、语义和即时回退，只替换已就绪时的paint。直接记录原生段落，没有白蒙版染色、额外整段TextPainter排版或图片读取回CPU。
- 按当前原生像素密度生成完整正文图片，32逻辑像素保护边缘，不降低密度；单图≤2M像素、4096边，DPR1～4。当前、下一行、上一行可请求，远行/超长/不支持的样式仍原生绘制；复杂彩色字形、阴影/背景Paint/装饰保持原回退。
- 布局完成后排入已有空闲资源队列，按焦点优先准备，单次图片完成后释放租约，再间隔调度下一任务。新增正文工作不允许在自动行滚动、手势/惯性或路由过渡中启动；不等缓存就绪才显示，不在paint/每帧生成图片，没有新Ticker或预热轮询。已开始的GPU任务无法强行取消，不声称系统完全零在途工作。
- 缓存身份包含完整文字、不透明原始RGB/样式、对齐、方向、语言、缩放/密度及排版条件；alpha变化保图像，字号/颜色/宽度等失效。RGB真正变化时回到原生路径，避免复活401已失败的统一染色方案。
- 正文与普通光晕共用 `LyricRasterPool` 的8M RGBA像素总额，约32MiB图片数据；排队/生成中/就绪全部计费，完成或取消按实际归属释放。优先当前正文/光晕、下一正文/光晕、上一正文等。压力下部分相邻/第二相邻光晕保留原生绘制，原效果强度与像素不变。该上限不包括Flutter自身RasterCache、GPU驱动和逐字/弹性既有缓存，不能当作进程内存上限。
- 本次采用原生密度图片在原1～1.1倍外部缩放中复用，减少字形反复准备。静止原生像素门槛保持；没有宣称每个缩放中间帧与引擎重新提示后的字缘逐像素相同。

### 默认轨迹及焦点属性

- 默认/动感使用已有 `LyricNormalizedMotion`，620ms基准、长行最多加60ms，单调、有限收束、无弹簧过冲和距离吸附；同向密集目标承接当前速度。逐字开关只改变文字绘制，不切换列表驱动，因此开关切换不会重新起一条滚动轨迹。
- 同一 `LyricFrameClock`推进列表及 `LyricSharedFocus`；缩放、颜色/alpha、动感间距、焦点模糊直接读取该进度。原隐式状态停止各自controller，保留已有合成组件和布局；文字样式仅局部更新，模糊发布给原RenderObject。
- 新段开始时先以旧进度冻结每个保留tween的可见值，再接续新目标，不将焦点目标先跳至起点。列表没有位移的边缘焦点切换也有同一有限进度。
- 手动浏览切回原本地属性动画，恢复自动跟随后重新接续共享进度；字体/窗口变化与seek仍按现有立即定位及重锚逻辑处理。切到弹性模式时两个列表模型同步当前偏移，弹性原回弹/物理行保持。逐字媒体时钟、词边界、7%上浮、翻译处理和394背景混色算法不改。
- 新资源调度已经让正文预热避开滚动繁忙帧；未额外关闭或重写动态背景、模糊、光晕来换取分数。
