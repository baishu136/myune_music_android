# Android 401：普通歌词缓存与焦点资源调度

日期：2026-10-16。版本 `1.0.0+401` / 正式ARM64 `2401`。基于400完整源码ZIP，保留398～400未提交成果及全部历史产物。本轮落实普通歌词缓存覆盖、临近行优先预热和换行边界降峰方案；不更改滚动轨迹、620ms焦点交接、透明度层级、模糊、光晕、逐字时序、背景或音频。

## 已实施

### 普通文字的原生RGB与透明度分离

398仅对白色普通歌词固定字形，灰色/彩色文字会回退到原生文字的逐帧颜色更新。401对普通单色文字保留原生RGB、以不透明源文字配合独立透明度合成。距离透明度交接不再替换原生段落，覆盖白字、灰字及相同RGB的彩色文字。`Color.lerp`对相同灰色RGB可能产生机器精度浮差，容忍≤1e-12的通道差以复用原值，不按8位颜色量化，不量化媒体时序。

跨RGB的真实变色仍使用原生RGB文字绘制，保留字形边缘；Paint、阴影、装饰、彩色emoji等仍走原生回退。文字与光晕独立合成，不把整行文字/光晕套统一alpha。

曾尝试白色字形统一染色：软件像素在彩色文字边缘最大误差36/255，超过既有≤3门槛。该候选已撤回并单独留档。最终原生RGB路径通过原398前景平均差<.25/255、最大≤3/255的完整对照；没有放宽门槛，也不声称任意彩色过渡完全只做合成。

### 焦点优先的有界光晕池

旧预算按挂载先后占用，先挂载的远行可能用完预算，正播/下一行仍走昂贵备用绘制。新增 `lyric_glow_pool.dart`，仅跟踪现有懒挂载窗口内的行，按正播、下一行、退出侧上一行、下第二行、其他距离排序。相同排名按稳定注册序号决定，避免多个列表竞争时反复换入换出。

全局仍是8M RGBA像素（额外约32MiB），单图≤2M、原生DPR 1～4、各边≤4096，光晕半径至少6且满足原资格；没有增大图像预算或降分辨率。需要时让较远缓存让位；未准备好或超限仍显示完整原生效果，不等待、不空白。隐藏列表降低排名，仅在竞争预算时让位，空间充足时保留图像。

预算包含排队记录与已发起但未完成的图像。取消未开始的记录立即退还；已经发起的图像在完成/销毁后释放，避免新旧任务叠加突破上限。失败使用原生回退，不持续重试。宽度、字体、DPR及模式变化、销毁均取消旧任务并释放正确的一代资源。

### 提前、分帧准备与彩色光晕复用

普通光晕的Picture记录由Widget构建移到既有空闲调度，沿用串行租约及16ms启动间隔分批准备；正播/临近行准备可在自动歌词跟随期间补齐，手势、惯性和路由保护继续阻止冷准备。其他行使用较低优先级等待空闲，不引入新逐帧时钟或周期轮询，不保证GPU异步任务生命周期完全不重叠。

调度的 `runIdleResource`增加可选动态优先级，排队期间换行会读取最新焦点。物理弹性路径默认行为保持。普通光晕保留白色光晕源及独立RGB着色；原生有色回退布局保留，白色源布局仅在需要时于空闲任务准备。准备完成后换焦点/颜色不再重建光晕布局或重生成图像，颜色及透明度依原规则显示。

临近行准备范围依然受现有懒挂载窗口限制；没有扩大整曲挂载范围。超长未挂载段落、首次必要布局、跨RGB文字变色、必要的动态模糊仍有实际绘制成本。本轮不是将所有情况严格改成纯位置合成，也没有GPU占用下降或零卡顿的真机证明。
