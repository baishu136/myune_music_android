# Android391：自动跟随纹理调度与歌词切页采样

2026-10-14，用户要求优化390真机压力测试中暴露的歌词绘制与切页开销。本轮交付1.0.0+391、正式ARM64 versionCode2391，未提交、推送或发布GitHub Release。原390产物保持。

## 最终改动

原调度器将自动歌词跟随也视为非空闲，逐字图集、覆盖校准、着色器准备及弹性光晕图集可能一直等待滚动结束。密集切行时滚动持续不结束，昂贵备用绘制便长期存在。

现在仅歌词列表的自动跟随保护声明 `allowResourcePreparation=true`；只有所有视觉保护均属于这类自动跟随时，显式选择 `allowDuringVisualAnimation` 的currentVisual/userVisible资源才可启动。每次仍只发一个租约，释放后至少间隔16ms，原字形校准1.5ms/着色器2ms分段预算、图集像素上限、队列代次及失效释放保持。手势、惯性、路由、普通视觉过渡和后台任务保持阻塞，自动跟随与普通页面淡入并存时也不能绕过保护。

歌词页入退场缩放增加 `FilterQuality.low`，让复杂歌词滤镜通过图像滤镜采样缩放；封面Hero、入退场时间/曲线、歌词几何、逐字7%上浮、真实时序、颜色、普通行40/32/25/20/15%、模糊/光晕参数和动态背景算法保持。没有新增设置或附注。

以下两个候选不在最终源码中：

- 普通白字整行外层alpha：降低源重绘，但改变文字与光晕source-over后的亮度。像素对照均差1.0813超过0.25阈值，未放宽阈值，完整撤回；旧相位绘制和光晕alpha恢复。
- 每行缩放均使用low采样：真实默认页没有可信收益，亦撤回。最终仅播放页整段歌词入退场采样保留。
