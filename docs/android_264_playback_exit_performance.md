# Android 264：退出播放页性能优化

日期：2026-09-12

## 问题定位

- 真机历史帧数据表明，退出播放页时保留全屏背景模糊会使 Raster P95 维持在约 25.2 ms；移除全屏背景模糊后降至约 15.1 ms。封面 Hero 并非主要瓶颈。
- 返回动画会同时绘制主页和播放页；此时实时高强度模糊、流体背景刷新、歌词实时效果以及播放页整树重建叠加，容易在首帧形成明显卡顿。

## 实现方案

- 保留全部背景自定义参数与视觉强度，在交互空闲期由独立 isolate 生成 320—480 像素宽的预模糊 JPEG。页面显示和封面 Hero 不等待该任务；缓存尚未就绪时继续使用原实时模糊作为兼容回退。
- 预模糊结果按封面、尺寸和模糊半径复用，采用最多四份的 LRU 缓存，避免内存无限增长。预解码也只在空闲调度许可后执行。
- 返回动画开始时通过局部信号立即停止流体背景 ticker，并仅冻结歌词子树；不再为这一状态变化重建整个播放页。
- 页面前景、封面加载、Hero 动画与所有现有功能保持原路径，不通过延迟首屏组件换取返回性能。

## 预期影响与回退

- 首次遇到尚未缓存的背景时会暂时显示原实时模糊，待空闲预处理完成后切换为静态模糊图；因此不会出现空白背景，但极快进入后立即退出的首次操作收益可能较小。
- 每份缓存解码后的典型显存占用约 1 MB，最多四份；编码与模糊在后台 isolate 完成，不占用 UI isolate。
- 自定义图片不可读、解码失败或设备忙碌时自动保留原实现，不影响页面使用。
