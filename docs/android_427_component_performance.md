## 已实施

1. **底部选歌面板**：原Consumer在每次歌词行等广域通知时重新扫描、拆分歌手并搜索整份乐库。现在只缓存当前一个派生列表，歌曲仍引用原Song对象。按乐库版本、来源对象及长度、范围、当前歌手/专辑、分隔符和查询失效；搜索另跟踪拼音索引准备状态。切歌、更新元数据、导入/隐藏/删除、修改分隔符、索引完成后仍会更新。保留原通知与歌单实时读取，避免遗漏可变歌单和封面变化。
2. **主页歌手/专辑及其详情**：统计模型新增收听数据版本，仅记录次数、导入和清空时变化，累计时长变化不增加此版本。两页及详情按版本订阅；归一化次数表由StatisticsManager按版本共享，防止每次暂停计时等无关通知触发所有歌曲汇总、组排序与代表封面选择。保留原排序、最常听突出、置顶、播放全部、多选和返回。
3. **切歌筛选和歌曲信息**：原getSongStatByPath每查一首歌都调用songStats，从而复制整张统计表；大量候选被跳过时可形成平方级复制。现在直接从模型内部Map读取对应项，仍使用原精确路径规则；统计排序也复用同一归一化快照，保留排序时快照语义。原对外songStats快照接口保持。
4. **歌曲行**：只订阅实际使用的“显示专辑名”，避免修改歌词字号等设置时重建独立歌曲行；主题仍由Theme依赖更新，封面仍监听原封面信号，正播和多选仍分别订阅。面板上层仍可能按真实数据通知重建，不宣称所有行更新路径均消失。
5. **歌词时间定位**：播放控制器和桌面歌词共用区间查找，正常仍处于同一行时只检查当前边界，跨一行可直接定位；seek/跨多行/无效提示退回二分。歌词页跳转定位也由线性遍历改为二分。相同时间戳仍取最后一行，首句前仍-1，不改变歌曲进度、设备补偿、逐字时间戳或视觉时钟。
6. **逐字平滑推进**：KaraokeSweepTimeline记住最近一段时间区间；同一字/段内连续帧、暂停重绘直接复用该段，越界或反向跳转回到二分。三次插值、速度曲线、上浮、缓存、颜色与帧率不改。
