# 404 真机歌词滚动卡顿与位移诊断

2026-10-17。任务为检测原因并给出最优修复方案；本轮未修改正式运行代码、递增版本或重新发行 APK。原 404 源码 ZIP、APK 和备份保持不可变。隔离原型用于验证原因，不能直接当作正式修复交付。

## 结论

卡顿与微小回退是两个已分别复现的问题，应组合解决：**先把临近普通歌词的首次字形绘制准备移出换行帧，再把默认滚动改为有限时长、无过冲的轨迹，并让焦点变化共享同一进度。** 仅调整弹簧收尾、增加 RepaintBoundary、关闭背景或模糊都不足以解决这两类问题。

1. 绘制冷开销有直接真机跟踪证据：一个 FrameTiming 的 UI 为 **1.124ms**、Raster 为 **41.359ms**，对应绘制调用中的 `CreateGlyphAtlas` 为 **35.023ms**。不是这帧界面计算耗时过长。冷阶段不采集 Timeline 的独立复测仍有 55.254ms 绘制尖峰。
2. 默认弹簧确实越过终点再返回。40 号字的长折行样本每次过冲约 **0.422～0.462 逻辑像素**，在本机 DPR=3 时约 **1.27～1.39 屏幕像素**；完整结束需要约 **1.18～1.29 秒**。焦点大小/颜色等主要变化约 620ms，列表仍在拖尾，容易形成“落稳后又动一下”的观感。
3. 隔离原型把普通歌词改为单调有限轨迹，七次完整长行滚动的反向采样从 **124 次降至 0 次**，约 **679ms** 结束；同一原型内未改变轨迹的逐字对照仍有 124 次回退。原型冷绘制仍有 **57.005ms** 尖峰，完整播放页 40 号字 P95 还升高，因此不能宣称单改曲线解决了卡顿。

## 卡顿的直接证据与推断范围

`cold2-vm-timeline.json` 捕获以下同一时钟上的嵌套事件：

| 事件 | 开始时间(µs) | 持续(ms) |
| --- | ---: | ---: |
| GPURasterizer::Draw | 137692589940 | 41.392 |
| SurfaceFrame::Encode | 137692590208 | 40.561 |
| CreateGlyphAtlas | 137692590893 | 35.023 |

对应 FrameTiming `[137692587500, 1124, 41359, 137692631312]`。重事件在第4行切换约 399ms 后，仍处于滚动和焦点变化期间。这确认**字体绘制资源准备进入了关键帧**。具体是哪组新字形、缩放档或资源重分配触发，当前无 CPU 调用栈，不能进一步断言“每帧重建整个图集”或“所有尖峰都是字体”。

普通歌词当前 `LyricPlainForeground` 复用不透明原生 RGB 的 Text/RenderParagraph，再单独改变透明度；它保留排版结果，并未将普通正文变为可直接复用的整行图片。已有 `lyric_glow_pool` 主要缓存外发光，本次外发光关闭，不能将已有光晕图片缓存当成普通正文已预先绘制完成。原生段落保留、RepaintBoundary 存在都不保证首次文字资源准备不会落到动画帧。

逐字组件有另一套字形图片准备路径，同条件下表现较好，支持复用该思路，但本轮没有证明逐字在所有内容中无尖峰。暖缓存普通40与无背景组非常接近，说明缓存顺序的混杂很强；背景有持续成本，但不是根据这组数字就可认定的唯一主因。关闭模糊后仍有63～71ms尖峰，也排除了“只要移除模糊即可根治”。

Timeline 环形缓冲会截断早期事件，14秒请求不代表有完整14秒事件。较短采集明确命中上述重帧。VM CPU profiler 返回 Feature disabled，`cold-cpu-samples.json` 保留失败；不能把后台 ConcurrentMark 的39ms等同于 UI 停顿39ms。最早 geometry 跟踪脚本错过目标窗口而退出，失败记录保留。

## 位移与落位观感

普通40基线七次完整滚动：每次约303.6或277.2逻辑像素，回退约0.462或0.422像素。全组124个负向步进，**累计**3.203像素；单次最大负向步进0.099像素。关闭模糊/背景、暖缓存后同样出现，逐字同轨迹对照也有，故不是上述特效独有的问题。

geometry40对第2～12行采样，文字水平坐标范围均为0；移除行位置与预期缩放后，垂直中心残差最大约1.7e-13逻辑像素。**本次样本没有证据支持字体横向重排或行内中心漂移**。所见微移可以由列表过冲回退解释；不推广为所有歌曲/切页/seek永远不存在布局变化。

普通40基线滚动启动±150ms的 Raster P95为17.81ms、最大66.77ms；结束±150ms P95为10.44ms、最大14.48ms。即本样本“结束不舒服”并不对应同等严重的掉帧，而更像长拖尾与微小回退。不能将启动、行中与落位混成同一个平均指标。

404将小距离吸附改为80ms连续收尾，只修正原来的吸附，`.90`阻尼弹簧自身的过冲仍在；一再修改收尾阈值不能消除该根因。

## 推荐实施顺序与边界

### 1. 优先处理普通正文冷绘制

- 复用真实排版结果，将当前、下一行及刚退场行的正文预先绘制为原生 RGB 图片；按邻近焦点排序，后台空闲分批生成。歌词加载完成、封面页空闲时即可准备；换行帧只取已就绪结果，不临时整行生成图片。长折行及翻译使用同一稳定几何。
- 按本机像素密度并考虑最大1.1倍缩放，验证足够分辨率，不通过降低清晰度取得分数。保留复杂文字/emoji/特殊 Paint 的原生回退；跨 RGB 变色应保留真实颜色路径，不能把401已失败的白蒙版统一染色方案复活。
- 普通正文和光晕应受同一有限像素预算管理，优先焦点及下一行，排队/在途资源也计入预算；以现有8M RGBA像素总额为起点，单图不超过现有2M约束。图像失效键含字体/字号/字重/宽度/密度/方向/文本与原始RGB，显示就绪后才切换绘制源；取消、销毁、失败必须释放。
- 不提前缓存全曲，不在每帧排版、创建图片或全表扫描，不增加“等缓存好了才显示歌词”的显示门槛。即时冷进入或超长行可能仍走原生回退，应实测残余尖峰，不承诺理论零卡顿。
- 该部分本轮尚未实现图片缓存候选，**性能收益待严格真机 A/B 验证**。35ms事件是选择这一优先级的依据，不是收益证明。

### 2. 同时去除默认轨迹的过冲与多套收尾

- 默认模式采用有限、单调、起终点平滑的时间轨迹；建议以现有620ms视觉节奏为基准，长折行最多增加约60ms。使用现有 `LyricNormalizedMotion`，不另造新驱动；密集换行继承当前速度，禁止普通跟随过冲回退或阈值吸附。
- 滚动、正播/退出行缩放、透明度和模糊焦点取同一过渡进度，而不只是配置相同时长。复用现有帧时钟，通过绘制/合成属性更新；继续保留列表虚拟化、手动浏览、命中测试、横滑切歌和原模糊/光晕效果。
- seek、暂停恢复、尺寸变化、开关逐字时，驱动要从当前可见姿态安全交接。弹性模式保留用户要求的回弹，只在指定行效果出现，不叠加第二个列表回弹。逐字媒体时间和单字高亮时序保持独立，不能为消除行滚动回退改写演唱时间。
- 本轮原型仅普通默认/动感路径选单调驱动，并对齐焦点时长/曲线；未完成所有隐式控制器共用进度、运行中切换驱动安全交接，**不得直接复制为发行修复**。逐字/弹性未改，是内部对照。

### 3. 最后再优化背景调度

先完成正文与轨迹修复，再相同温度/相同缓存条件交错验证394背景与焦点绘制的竞争。只安排新增预热任务避开忙帧；必要时复用背景已有帧预算调度，不改变背景混色算法，不默认关闭动态背景、模糊或发光。

### 验收

- 先用普通40长折行复现旧回退和字形重帧，再进行同一文件/同一歌词时间轴、37.6/32/40字号、W800、原背景/模糊条件下交错 A/B 和多轮冷进程测试。
- 分别统计行启动、中段、结束±150ms的 FrameTiming 和实际呈现间隔；不能只看平均或总体P95。目标是回退0、有限时间结束、关键行不再触发耗时字形资源准备；改善必须多轮重复，不强行宣布120fps。
- 再覆盖真实/估算逐字、开关切换、密集/长间隔行、翻译、混合文字/emoji、手动浏览/seek、暂停恢复、12次切页、后台返回及资源预算。普通文字/缩放/模糊/光晕维持既有像素回归门槛，不放宽401颜色失败阈值。
