# Android 371：逐字推进连续性与封面切歌词入场修复

日期：2026-10-08。版本 `1.0.0+371`，显示 `1.0.0-android.371`，正式 ARM64 versionCode 2371。按用户授权修复前轮诊断的问题及封面页切至歌词页的行闪烁。保留 361–370 的脏工作区、源码与全部产物，没有提交、推送、发布 Git、卸载或清空数据。

## 复现原因与修复

### 媒体时钟和普通位置样本

370 重新订阅共享帧时钟时 `_frameOrigin` 重置，但已经 running 的媒体时钟沿用旧 elapsed。隐藏歌词入场或 seek 保护期间重复构建又反复校准同一目标，下一帧可倒退。原诊断中真实列表的 210ms 目标在 50ms 后变成 −140ms；独立时钟得到 −740ms。报告保留在 `F:/AGENT/1/test-artifacts/karaoke-stall-diagnosis-370/diagnosis.md`。

371 每次重新订阅显式 `rebaseElapsed()`，保留当前媒体位置和剩余 seek 保护，再绑定新 elapsed。`tick()` 遇到 elapsed 反向重启也重绑定，下一帧继续推进。`entryPreparing` 只在 false→true 时校准；同一 seek 目标只在目标改变、歌曲身份改变或成为当前行时校准。入场期间重复父组件构建不会把扫光和亮度包络归零，保留同一塑形缓存。

普通位置更新与显式 seek 分流。`KaraokePositionSampleTracker` 同时用于真实列表和行媒体时钟：对重复/小幅倒序样本保持原锚点；普通样本采用有界漂移校正；中等异常样本等待另一份相符样本确认位置迁移，超过 1s 的漂移立即作为跳转。普通纠偏每帧为正常步长的 ±8%，不再因为 80ms 滞后进入原来的四分之一速，也不把 180ms 延迟安装成列表 seek 锁。超过 120ms 的长帧仍按经过时间推进，不能因延迟锚点而反向跳回。

显式 seek notifier 和 `seek()` 仍立即定位，包含小幅前后跳转、原保护、暂停冻结和倍率。原生位置消息没有源采样时间或 seek 代际，因此未标记的跳转仍通过启发式样本过滤识别；不能承诺所有外部小跳转都与延迟样本完全区分。

### 冷图集和封面→歌词显示

370 普通 token 图集未完成时跳过高亮，只显示未唱底字；图集完成后高亮突然出现。同一媒体位置的诊断已证明 highlights 从全零变为正数，未测得图集耗时。

371 在缓存构造阶段为所有 token 录制完整塑形片段，冷图集阶段立即按当前媒体位置绘制矢量扫光，不在 paint 内临时排版。尚未全部完成的 shader 不进入绘制；整组资源完成后一次切换 ready 并通知，避免分批初始化过程中读到半成品。普通 token 的临时矢量 mask 在图集就绪后释放；复杂塑形/彩色字形继续保留原有安全回退。缓存尺寸、折行、真实 token 时间与高亮覆盖规则保持。

封面切歌词通过实际 `MobileLyricsList` 的隐藏 TickerMode、入场准备和重复构建路径验证：只校准一次，当前行缓存保留，入场结束后继续前进。修复了已复现的时钟回退和冷高亮等待机制；没有录到当前手机的完整滑动过程，不能据组件测试宣布所有视觉闪烁已在真机消失。

### 准备调度与生命周期

- 下一行从当前行开始后即可准备，不等到原 80% / 最后 400ms。仅当前行和紧邻下一行/一个备用缓存，没有全曲图集预加载。
- 未挂载下一行的构造与即将进入缓存区的行构造取得空闲许可，重新检查代际、当前行、浏览状态和所有权。许可只覆盖同步准备，不跨越异步解码等待。
- 歌词缓存的图集任务串行执行；`toImage` 和 program 加载启动接入 `currentVisual` 空闲资源许可。异步等待释放 UI 许可，不阻塞其他拥有者。
- 普通字形 shader 每批最多 32 个，或批次计时达到约 2ms 后释放并重新排队。单次 shader 创建及栅格化仍可超过预算，这不是硬实时上限。
- 新增 `cancelIdleWork()`，行/列表/缓存销毁或失效立即取消属于自己的排队请求，不解除其他过渡保护，也不抢占已经授予的许可。旧异步结果不采用并按原规则释放资源。
- shader program 和图集串行尾指针只保留进行中的 Future，完成后清除。已加载 program 返回当前调用上下文的 Future，避免测试跨 FakeAsync zone 缓存已完成 Future 而停滞；不重复加载 program。
