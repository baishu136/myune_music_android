# Android 383：歌词滚动与高亮连贯性

2026-10-12；1.0.0+383，正式ARM64 versionCode2383。

## 已确认的路径和修改

1. 生产列表使用解析弹簧，但每次advance最多接收50ms，延迟帧之后丢弃剩余时间，导致列表继续落后于墙钟。解析分支改为接收完整可见帧时间；不稳定的数值积分兼容分支仍保留保护。前后台/隐藏时长继续由379共享时钟排除，并非恢复后追赶后台时间。
2. 旧弹性模式先jumpTo目标，再用带距离启动延迟的各行弹簧补偿整段位移。现使用与默认模式相同的列表驱动，各行仅叠加有限、立即启动的修正；新挂载行使用原脉冲时间，不重放过期动画。
3. 真实词元的逐字扫光路径包含排版侧边留白。软件MiSans/I山l中、600ms真实词元测量：原I从视觉窗口-45ms至真实起点的4个15ms样本总亮度均0，起点后15ms仅24；校准后为0/24/202/452，起点后15ms829。只是该软件样本的RGB和，不能推断所有字形或设备。
4. 在原图集和原白色覆盖图就绪后，读取实际字形所有权与墨迹边界，缓存横向扫光路径；不裁剪字形、descender/overhang，不改源词元时间或7%上浮。维持既有最多45/60ms视觉窗口和复杂/彩色/连字原生回退。冷图集未就绪时仍使用原塑形回退，不保证冷帧零停顿。

## 弹性观感

- 正播行正常退场，缩放增加慢起步、加速及轻微回弹：进度最大超出目标.055，实际缩放约0.55%。即将正播行前70%保留默认曲线，后段叠加轻微回弹，实际缩放变化不超过约0.45%。颜色/透明度/模糊曲线不使用越界缩放曲线。
- 到达/退场行位移限幅字号10%，其他行字号34%；其他行随距屏幕焦点/边缘的距离提高修正幅度。修正约540–720ms，有限单次回弹，端点位置/速度归零；中途重定向保位置和速度，不清零重启。主列表始终沿默认轨迹，没有等待阶段或第二个整距离驱动。
- 含汉字的歌词按实际排版行（含折行/译文）分别运动；保留完整原生塑形和段落对齐，逐字上浮与行弹性独立。每个物理行共享该段缓存；正文、静态文本、译文和光晕同步采用相同位移。普通歌词与逐字歌词都使用该效果。
- 行上下安全间距各5→6dp，条目总间距小幅增加约2.2dp（含原1.1尺度预留）；基础行高1.2和7%上浮比例不变。

## 开销控制与限制

- 沿用一个共享VSync。可见行（含预留边缘）才订阅弹性；位移按物理行算一次并复用typed buffer，播放帧不排版、测量墨迹、构建字形widget或重建图集；修正结束即退订。显式seek、换曲、隐藏准备和几何重定位取消旧脉冲。
- 墨迹测量只在已有串行图集任务中做一次；临时两份RGBA总量≤4MiB，ID边界表约4KiB，最多8192像素或约1.5ms CPU一批，再让出事件循环并重取空闲许可。回读/单次GPU操作并不保证≤1.5ms；最终路径组装仍有一次性成本，原生回退保原路径。
- 中文静态前景缓存物理行Picture，使用一层或正文/译文两层着色以保留颜色与alpha，仍有合成成本，不宣称零栅格占用。形状与颜色分开，颜色过渡不重新塑形。光晕缓存白色形状并分离着色，异步准备单段≤1MiB/最长边4096的纹理，各行复用；删除/换几何取消并释放。失败保矢量回退，不持续重试或关闭光晕。
- 很长/很密的段落仍有与文本量相关的首轮布局/记录和绘制成本；没有把所有冷初始化移出首个必要帧，也没有在无设备数据时关闭特效、降低背景质量或宣称GPU/功耗改善。
