# Android397：普通歌词滚动启动与落位的重复工作

2026-10-15。用户报告关闭逐字歌词时，歌词行滚动在启动和落位有明显卡顿；ADB本轮未检测到设备，用户明确“先完成代码修复，稍后连接”。本轮先交付代码与ARM64 APK，不安装、不更新Launcher、不推送/发布GitHub。版本1.0.0+397，保留396产物与全部脏工作区成果。

## 已复现的结构问题

- 396已去掉模糊动画中途的逐帧setState，但`_AnimatedLyricBlurState._motionChanged()`仍在visualMoving从false↔true时对所有挂载行调用setState。普通歌词每次完整滚动都有开始和结束，这些额外重建集中在两个边界。新增测试只改变生产控件的真实motion信号，旧版在参数不变时仍替换所有LyricViewportBlur Widget，失败记录`red-boundary.txt`。
- 396的RenderLyricViewportBlur在sigma归零时将isRepaintBoundary切为false，后续变模糊又切回true。正播行清晰落位和下一轮离开焦点会改变合成边界，旧版零点身份测试失败。本机Flutter SDK也说明：动画中的滤镜层反复移除和重建可能比保留外层更昂贵。本轮不把结构复现等同于真机唯一根因或零卡顿证明。
- 逐字开关关闭时，逐字适配检查原来仍对整首每行执行返回false的回调；普通歌词没有必要扫描这一遍。

## 修复

- 每行保留一个ValueNotifier与Animation代理，原controller/tween/curve继续计算相同sigma。控制器tick或motion边界只发布变化数值，渲染对象接收；不再靠setState重新绑定动画。初始值、切换曲线、密集换焦点、隐藏准备、原地seek与监听销毁仍由原生命周期处理。
- 外层固定使用同一个OffsetLayer缓存边界。实际需要模糊时，在其内部复用同一个ImageFilterLayer并更新原滤镜；sigma归零时直接绘制子层，不执行零半径模糊。切换只重接缓存子层，不改变整条RenderObject的合成属性。内部layer由LayerHandle持有，销毁释放。
- 外层稳定也有成本：相较396，模糊行多一层轻量OffsetLayer，清晰行也保留边界；没有新建位图缓存或计时器，不能在未测真机时声称GPU/内存必定下降。
- 关闭逐字时立即返回不适配，不扫描歌词列表。普通/逐字滚动驱动、弹簧参数、620ms焦点曲线、亚像素尾部、文字透明度、模糊精度、光晕、字号、7%逐字上浮、394动态背景以及音频均不改。没有新增选项/附注。
