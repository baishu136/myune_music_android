# Android 351：移除封面光圈、微调逐字上浮与主页切页调度

日期：2026-10-03。以实际 350 工作区为基线，版本更新为 `0.9.9+351`。保留既有未提交成果，不重置、不提交、不推送；所有 Android 构建仅 ARM64。

## 修改与依据

1. 播放页封面直接使用原有 `NowPlayingCoverHero`，移除边缘光圈包装和无其他用途的 `now_playing_cover_glow.dart`、其专属测试。封面更换、Hero、动态背景和 350 的视口边缘歌词景深均保留。两个移除文件可从 350 源码留档恢复。旧真机夹具改为断言没有光圈，不改变其他测量段。
2. `KaraokeMotionConfig.liftHeightFraction` 从 `.045` 增至 `.055`，基准是排版行高，不是字号。32/40/48px 行高分别增加约 `.32/.40/.48px`，仍限幅 1.2–4px，小字号最低限幅附近可能没有变化。保持 760ms **媒体时间**、到顶缓冲、错开程度、高亮和退出规则；没有增加新的运动路径、布局或 ticker。
3. 实际 `PageView` 开启 `allowImplicitScrolling` 时，0→1 滑动在目标歌单页以外，会首次构建不可见的第 2 页（歌手）。先补复现测试，旧版此断言失败。此工作与滑动/标题动画重叠；348 记录也有首次歌手页尖峰，但本轮没有 CPU 调用栈证明全部来自拼音初始化，故不改分组算法。
4. `HomeTabViewport` 在冷页仍未全部准备时，滑动开始临时关闭隐式相邻预排；保留可见两端、页面 KeepAlive 与 RepaintBoundary。滑动停止后等待 180ms，再通过已有交互调度器申请空闲工作，持有 lease 至预排帧完成。原 320ms 切页、380ms 标题动画、手势与非相邻跳转规则不变，没有动画逐帧全局 `setState`。
5. 首轮真机结果显示，所有已缓存页面也反复切换预排状态会增加尖峰。因此最终只在仍有未首次挂载页面时抑制预排，所有有限主页都挂载后保持原缓存策略，减少两次多余视口布局。准备记录最多为主页数（当前 5），控制器或数量变化时清理；定时器、空闲等待有 revision 防护，快速反向导航与销毁取消过期任务。

## 真机 Profile 对照

设备：vivo V2352A / Android 15。350 源码留档在独立目录解包，仅加入同一 `home_switch_performance_test.dart` 夹具，不修改主工作区以回退代码。350 与 351 均采用 ARM64 **Profile**，同一实际 146 首曲库、自定义主题和原曲；测量期间暂停音频，不录屏。未更换歌曲、清空曲库或修改设置。每版测 18 次页签跳转、一次横向手势和一次快速反向跳转。

动画窗口为操作起点后 420ms（320ms 滑动、380ms 标题、调度余量）；另保存操作后 1100ms 的整个窗口，**不隐藏延后预热成本**。接口标称约 120Hz，实际样本 vsync 中位间隔约 16.585ms，因此按约 60Hz / 16.67ms 统计，未验证真机 120Hz 满帧。

结论仅限这轮样本：冷构建尖峰从可见切页阶段移到空闲准备阶段，动画窗口超预算样本减少；整个窗口没有变成零尖峰，P95 也没有整体降低。最终仍有一次热返回 Build 17.35ms，以及三次延后冷准备超预算，**不满足全程满帧，不进行 Git 提交**。非相邻跳转的可见桥接冷页、曲库数据变化等场景仍可能有耗时，不以此次局部优化宣称全部消除。

保留原始 vsync/build/raster 数据和探索轮，不挑选单个参数作为连续性证据。测试是顺序跑的单设备采样，没有严格随机化/热状态控制；没有独立 GPU 内存、功耗和长期内存稳定性结论。Profile 依赖版本、资源、Dex 相同；两项 JNI 小库只有 20 字节 GNU build-id 差异，大小及其余字节一致。APK 容器大小不同不代表加载代码或帧耗时变化。
