# Android 347：宽域漫射、真实暖色与慢速演化

日期：2026-10-03。以实际工作区346为基线；保留其全部未提交成果，不改播放器、歌词时钟、歌词滚动或页面设置。

## 查明的问题与最终参数

- 346光场在指数衰减后又做平方，实际边缘比公式更陡。改为 `exp(-pow(max(d², .00001), .65) * 1.25)`，不再平方。四色半径依次为 `(.85,1.05)`、`(.80,.95)`、`(.75,.95)`、`(.80,1.00)`，仍保留分散漫游和双层低频域扭曲。
- 演化时钟只在Shader乘一次 `.28`。当前346没有额外时间系数，因此这是相对346降低72%，不是降低40%；遵循本轮明确数值，不宣称与Salt实际流速完全相同。环境基线下单轴周期约76–109秒，FFT仍使用既有平滑速度包络。
- 同步将Dart相位回绕周期改为 `200π/.28`。仅改Shader系数、仍在200π回绕，会把波形切断；实际FragmentProgram测试覆盖三个RGB通道和回绕前后相邻帧。
- 暗角采用有定义的GLSL写法 `1-smoothstep(.35,1.10,dist)`，相当于用户提出的反向暗角，避免反向smoothstep的未定义行为。暗角增益 `.90→1.05`；全局暗化 `1-clamp(dim,0,.60)*.25`。Painter同步取消旧 `.20` 最低遮罩，实际dim=0可以生效；不重置已有设置值。
- 第三/第四光场相对增益分别为1.35/1.15。每场每通道能量上限.98，防止高彩暖光超过1后Screen透射变为负值；输出仍是不透明单次drawRect，无新纹理、模糊或saveLayer。
- 真机初次检查发现，扩大光场、去掉平方后仍沿用普通彩色封面的 `.92` 总光强，会叠成过浅背景，白色正文不易阅读。因此最终普通彩色封面总光强校准为 `.50`，只在取色阶段决定，不添加黑蒙层。暗色保持既有分类：无色暗封面.28、普通暗色.55、鲜艳暗色.70；非暗无色.30。指定半径、衰减、暖色比例、暗角与dim公式未改。

## 取色和色槽

- 可见封面像素中的暖色范围为Hue20–55°、饱和度≥.20、明度.08–.90；实际占比≥3%才锁定第三槽。不给纯冷色、黑白封面补造黄色，不把孤立噪声当成重要暖色。
- 64×64采样的暖色可能分散在许多小色桶中，旧top-32会丢掉整个暖色梯度。现在worker保留最有实际面积及彩度的暖色色桶，再合并其余真实暖色像素的RGB统计，与最多30个其他色桶共同返回；两部分占比各自准确、不重复计数，不虚报单色面积。不会把所有金色与浅肤色混成一个过浅的平均色。
- 实际Light Mellow画面进一步暴露近似色去重问题：浅人脸/纸色较先入桶，归一化后与同色相的高彩印刷接近，旧实现直接丢掉后来进入的高彩色。鲜艳封面现在保留同组中原始RGB色度更高的真实候选，不逐帧补彩；生成PNG回归覆盖了金色与肤色分离，保留原有粉红/青绿六选四回归。
- 四色选择后为暖色腾出第三槽，尽量替换最重复的辅助色，保留主导区域及粉红/青绿等有效颜色。增加 `warmAccentLocked` 元数据；切歌的最近色槽匹配只可重排其他三槽，否则刚锁定的暖色会再次被移走。
- 650ms五次平滑换色、连切时从实际显示颜色继续插值、离页快照均保留。元数据不参与Shader逐帧分析；颜色和总光能仍连续插值。
- 非暗且鲜艳、有真实彩度的颜色明度范围为.38–.68、饱和度上限.95；真实黑色、暗封面与低彩灰色不强行提升到.38。保护黑位和无色系，不以艳化所有封面换取单一样本亮度。

## 黑蒙层排查

检查 `FluidPlaybackBackground`、`PlaybackBackground` 和 `mobile_shell.dart` 播放页：流体分支直接作为透明Scaffold的背景，没有叠加额外30%–50%黑色遮罩。自定义图片/模糊封面遮罩属于另一条渲染分支，未修改。组件添加所有暗化交由Shader管理的注释，不添加多余遮罩或修改无关页面。
